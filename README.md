# ナンプレ

置くたびに気持ちいい音が鳴る、シンプルなナンプレ（数字を埋めるパズル）。毎日の「今日の一問」で、全員が同じ問題を解いて点数を競えます。

「数独」はニコリの登録商標なので、アプリ名には使わない。
iPhone では Safari の共有メニューから「ホーム画面に追加」すると、アプリとして遊べます（PWA）。

**プレイ: https://nanpure-game.vercel.app**

## 遊び方

- **アプリ内の遊び方**: ホーム右上の「?」か設定から開く。ルール・操作・点数・今日の一問の決まり・難易度と手筋・キー操作がある。
  - ホームから開いたときは、ネイキッドシングルの練習への入口もある。
  - 初めて開いたときは、ホームに案内を 1 行出す。閉じるか遊び方を開くと、それ以降は出さない。
- **難易度**: かんたん・ふつう・むずかしい・エキスパート・鬼・極。鬼は人の手筋では解けない水準、極は鬼の候補をたくさん作って、仮定を何段も重ねないと解けないものを選んだ問題。
- **今日の一問**: 難易度ごとに 1 日 1 問。全員が同じ問題で、最初のクリアタイムがランキングに載ります。日付は日本時間 0 時に切り替わります。
- **フリープレイ**: 好きな難易度で何問でも。ヒントと一時停止が使えます。オフラインでも遊べます。
  - クリアの結果の「結果を共有」で、同じ盤面を開く URL を文に入れる。受け取った人は、その盤面をフリープレイとして遊べる（「盤面の共有」を参照）。
  - 「盤面を入力」で、紙やほかのアプリの問題を手で入れて遊べる（「盤面の入力」を参照）。
- **手筋の練習**: 手筋ごとに用意した局面で、置けるマスに数字を置くか、消せる候補をメモから消す。ヒントで答えを見られる。解いた局面の数は端末にだけ残る（引き継ぎの対象外）。
- **クリアの結果**: 点数やタイムの下に、その問題に要る手筋と回数を出す（難易度の判定と同じ道筋で数える。遊んだ人の手順ではない）。ポインティングとクレーミングはロックドキャンディデートにまとめる。鬼・極のように手筋だけでは解き切れない問題には「手筋で進めない局面あり」と出す。共有する文には入れない。
  - その下に、このプレイで最初に置いた解答と違う数字を「最初の誤り」として「14手目 3行5列 7（正解 4）」のように出す（今日の一問・フリープレイ。練習は記録しない）。間違いの表示の設定に関わらず記録する。ミスが無ければ何も出さない。読み上げでは「最初の誤り」の欄（region）として読む。共有する文には入れない。
  - 何手目は数字を置いた回数で数える（ヒントで置いた分を含む。メモ・消す・色・戻す・進む・間違える前まで戻すは数えない）。
  - 戻す・消す・間違える前まで戻すで盤面から消した誤りも、最初の誤りとして残す（結果のミスの数と同じく、置いた事実として数える）。
  - 置く直前の盤面の数字だけから（メモは見ない）、そのマスに正しい数字をシングル（ネイキッド・ヒドゥン）で 1 手で置けたときは「その時点で確定できた手筋: ネイキッドシングル」のように添える。ロックドキャンディデートなどで候補を消してから決まるマスには出さない。調べるのは誤りを置いたときの 1 回だけ（`findAllSteps`。途中の盤面で 1 回 0.2〜2ms ほど。手元の Mac）。
  - 途中の盤面の保存データ（`sudoku:free`・`sudoku:daily:*`）に入れるので、続きからでも残る。ランキング・引き継ぎ・アカウントの同期には送らない。置いた回数を持たない古い保存データの続きでは記録しない（それまでの回数とミスが分からないため）。
- 操作: マスをタップ → 数字。メモはメモを ON にしてから数字。盤面をなぞるか Shift / Ctrl / Cmd+クリックで複数のマスを選ぶと、数字は選んだ空きマスのメモにまとめて付け外しし、消すはメモだけを消す。色を ON にすると、数字パッドが 9 色に変わり、選んだマスに色を付け外しする（消すは色だけを外す）。キーボードでは 1〜9、Shift+数字でメモ、矢印で移動、N でメモ切替、C で色切替、Backspace で消す、Z で戻す、Shift+Z で進む、H でヒント（今日の一問を除く）。
- **読み上げ（VoiceOver・TalkBack・NVDA）**: 盤面は 9 行の表（grid）で、マスは「3行5列 最初から 7」「3行5列 間違い 4」「3行5列 メモ1・3 空き」のように読む（色があればその後に「色2」）。選んでいるマスは選択中（`aria-selected`）として読む。
  - Tab で盤面に入ると、選んでいるマス（無ければ最後に選んだマス、初めは中央）にだけ止まる。矢印で選ぶとフォーカスも動き（選んでいなければフォーカスしているマスから動く。戻す・進むで選択が動いたときはフォーカスを動かさない）、もう一度 Tab で盤面の外へ出る。Enter・Space と読み上げソフトの操作（ダブルタップなど）でも、マスを選び数字を押せる。
  - 置いた数字（間違いは「間違い」を付ける）・メモ・消す・戻す・ヒント・クリア・練習の正解は、盤面の外の欄（`role="status"`）で知らせる。行き詰まりは今までどおり盤面の下の警告（`role="alert"`）で知らせる。
  - 実機の VoiceOver・TalkBack・NVDA ではまだ確かめていない。
- **記録**: 今日の一問の連続日数とカレンダー、合計プレイ時間（フリープレイのクリアと途中でやめた分、今日の一問のクリア）、難易度ごとの記録。難易度ごとの記録は、今日の一問がクリア数・平均時間・最速・最高点・平均点、フリープレイが始めた数・クリア数・クリア率・平均時間・最速（ヒントなし）・ノーミス最速（ヒント・ミスなし）・最高点。フリープレイの始めた数は記録を取り始めた版から数え、クリア率と平均時間はそれ以降に始めた・クリアした分で出す（平均時間はヒントを使ったクリアも含む）。
- **実績**: 記録画面に一覧がある。今日の一問・フリープレイ・手筋の練習の記録から判定し、新しく解除したらクリアの結果か練習の正解に 1 行出す。解除した日は端末にだけ残る（引き継いだ先では、移した記録から判定し直す）。
- **引き継ぎ**: 設定でコードを発行し、別の端末で入力すると、プレイヤー（ID と名前）とフリープレイの記録を移せる。コードは 24 時間有効で 1 回だけ使える。今日の一問の記録はサーバーにあるので、そのまま見られる。
- **アカウント（任意）**: ホームの設定の「アカウント」で、パスキーを使ってアカウントを作り、ログインできる（ゲームや練習の途中の設定には出さない）。ほかの端末やブラウザでログインすると、同じプレイヤー（ID と名前）とフリープレイの記録で遊べる。ログインしなくても今までどおり遊べる。
  - 作ると、この端末のプレイヤーをアカウントに紐づける。別のプレイヤーで遊んでいた端末でログインすると、そのプレイヤーの今日の一問の履歴とフリープレイの記録をアカウントに合わせてから、アカウントのプレイヤーに切り替える。
  - ログアウトすると、まだ送っていない記録をアカウントに送ってから、この端末の記録を消して新しいプレイヤーになる（消すものは「アカウント（パスキー）」の端末の動きを参照）。アカウントの記録は残り、ログインし直せば戻る。
  - アカウントを削除しても、この端末の記録とプレイヤーは残り、ログインせずにそのまま遊べる。
  - 手筋の練習の進み具合と毎日の通知のオン／オフは端末ごと（同期しない）。ログイン中は、引き継ぎの「コードを入力」は出さず（発行はできる）、旧 URL から移るときの受け取るシートも開かない（ログインの状態を確かめ終わるまで待つ）。
  - iPhone のホーム画面に追加したアプリは Safari と保存場所が別なので、記録もログインも別になる。両方でログインすれば同じプレイヤーで遊べる。
  - パスキーを失うと、アカウントに戻る手段は無い。
- 設定: 効果音・振動、間違いの表示、同じ数字や行・列・ブロックの強調、残りの数の表示、揃ったときの光、周りのメモの自動消去、ヒントの前の確認を、それぞれオン／オフできます。点数には影響しません。
- **表示**: 設定の「テーマ」で自動（端末の設定に従う）・ライト・ダーク、「文字サイズ」で標準・大・特大を選べる。端末ごとの設定で、引き継ぎ・アカウントの対象外。ピンチで拡大できる（盤面の上を除く）。しくみは「表示の設定」を参照。
- **毎日の通知**: 設定の「毎日の通知」でオンにすると、今日の一問を 1 問もクリアしていない日の 20 時（日本時間）に通知が届く。iPhone・iPad では、ホーム画面に追加したアプリ（iOS 16.4 以降）でだけ設定できる。端末にはオンにしたことだけを保存する（引き継ぎの対象外）。サーバーに保存するものは「リマインド通知（Web Push）」を参照。

## URL の移行

本番の URL を https://sudoku-xi-five.vercel.app から https://nanpure-game.vercel.app に移した。端末の記録は URL（origin）ごとに別なので、旧 URL の記録は新しい URL からは見えない。旧 URL も同じデプロイが配り、開いた端末側で見分けて案内する（`src/lib/client/move.ts`、`src/components/App.tsx` の起動処理）。

- 旧 URL で記録の無い端末は、同じパスとクエリで新しい URL へそのまま移る（旧 URL には何も保存しない）。
  - 記録は中身で判定する（`hasLocalData`）: 名前のあるプレイヤー、フリープレイの記録、途中の盤面、練習の進み具合、今日の一問の結果・途中の盤面、履歴、通知の印、通知をオンにしたまま移った印のどれか。開いただけで保存するもの（名前の無いプレイヤー・実績・空の履歴）と設定は記録とみなさない。見落とすと旧 URL の記録に戻れなくなるので、保存データの種類を増やしたらここに足す。
- 旧 URL で記録のある端末は、ふだんどおり遊べる。開くたびに「新しい URL へ移る」シートを出し（閉じられる）、ホームに閉じられない案内を出す。ホーム画面への追加は案内しない。
  - 「記録を移して開く」で引き継ぎコードを発行し、新しい URL を `/#code=XXXXXXXX` で開く。新しい URL では「引き継ぐ」を押したときだけコードを使う（開いただけでコードを使い切らないように）。新しい URL に記録があれば、置き換わることを示す。
  - 新しい URL が受け取るシートを自動で開くのは、旧 URL のページから新しく開かれたとき（`document.referrer` の origin が旧 URL で、読み込みの種類が `navigate`）だけ。開くのは、ログインの状態を確かめ終わってから、ホームでほかのシートが無く、ゲームを始める途中でもなくなったとき（それまでにゲームを始めたら、ホームに戻ってから開く）。ログイン中なら開かない。ほかのページから `#code=` のリンクを開いたときと、再読み込み・戻る/進むで開き直したときは、URL から消すだけでシートを出さない（他人が自分のコードを入れたリンクを送ったり、移った後のページの fragment を差し替えて読み込み直させたりして、1 回のタップでプレイヤーを差し替えるのを防ぐ）。
  - referrer を送らないブラウザや設定では、「記録を移して開く」を押しても新しい URL でシートが出ず、そのコードは使われないまま 24 時間で失効する。この場合は旧 URL の設定の「コードを発行」で出したコードを、新しい URL の設定の「コードを入力」で入れる（通知については既知の限界を参照）。
  - iOS のホーム画面に追加したアプリは Safari と保存先が別なので、新しい URL を開かずにコードと手順を出す。新しい URL をホーム画面に追加し、その設定で「コードを入力」する。
  - 旧 URL の記録は消さない（いつでも旧 URL に戻れる）。旧 URL への転送（307/308）は入れていない。期限を決めて旧 URL を転送に切り替える段階（フェーズ 2）も入れていない。
- 移るのは引き継ぎと同じもの（プレイヤー ID・名前・フリープレイの記録）。設定・練習の進み具合・途中の盤面・実績の日付・通知の印は移らない。今日の一問の記録はサーバーにあるので、そのまま見られる。
- コードはクエリでなく fragment で渡す（サーバーのログや Referer に残さない）。新しい URL は開いてすぐ、通信の前に fragment を読んで URL から消す。旧 URL で受けたコードは使わずに消す。旧 URL のページの referrer の扱いを変える（`Referrer-Policy: no-referrer` など）と、受け取るシートが自動で開かなくなる。
- 通知: 移るときに旧 URL で通知をオンにしていたら、コードを発行した時点で旧 URL の購読を外し、旧 URL の端末に「通知をオンにしたまま移った」印（`sudoku:moved-with-reminder`）を残す。新しい URL で受け取るシートが開いて引き継いだときは、その後に「毎日の通知」の項目を出す（オンにし直す）。新しい URL から旧 URL に戻ってコードを発行し直したときも、この印で項目を出す。旧 URL で通知をオンにし直すと印は消える。印は旧 URL の端末内だけで、引き継ぎには含めない。シートが開かなかったときは項目を出さない（既知の限界を参照）。移っていない端末の旧 URL の購読はそのまま届き、通知を開くと旧 URL で案内が出る（購読は最後の登録から 400 日で消える）。
- URL を変えるときは `src/lib/site.ts` の `SITE_ORIGIN`・`LEGACY_HOST` を変える（`<link rel="canonical">` もここから作る）。
- 既知の限界:
  - referrer が届かないなどで新しい URL のシートが開かなかったとき、旧 URL で通知をオンにしていた端末では、旧 URL の購読は外れたまま、新しい URL でも通知はオフのままになり、通知が止まる（画面には何も出ない）。「記録を移して開く」で出したコードは使われないまま 24 時間で失効する。戻すには、旧 URL の設定で「毎日の通知」をオンにし直すか、旧 URL の設定の「コードを発行」で出したコードを新しい URL の設定の「コードを入力」で入れてから、新しい URL の設定で「毎日の通知」をオンにする。
  - 設定の「引き継ぎ」で旧 URL から新しい URL へ移ると、旧 URL の購読が残り、両方でオンにすると通知が 2 通届きうる（旧 URL の設定でオフにすれば止まる）。
  - `#code=` の URL は、消す前にブラウザの履歴に残りうる（コードは 24 時間有効で 1 回だけ使える）。
  - iOS のホーム画面に追加したアプリの保存先が Safari と別だという前提は、実機で確かめていない。

## 盤面の共有

フリープレイの盤面を URL で渡す（`src/lib/client/sharedPuzzle.ts`、`src/components/App.tsx` の起動処理）。

- URL は `https://nanpure-game.vercel.app/?p=<81 桁>&d=<難易度>`。`p` は最初の配置（左上から行ごと、0 は空き）。シードではなく盤面そのものを渡す（極は端末とサーバーで候補の数が違い、生成の処理を変えても同じ問題になるように）。
- フリープレイの「結果を共有」は、この URL を文に入れる。今日の一問はアプリの URL のまま（盤面は共有しない。フリープレイでヒントを使って解いてから本番に入れるため）。
- 開いたら、通信の前に `p`・`d` を読んで URL から消す（ほかのパラメータは残す）。始めるのは「共有された問題を始めますか？」で「始める」を押したときだけ（ほかのページから開かせて、途中の問題や記録を書き換えられないように）。「やめる」なら何も変えない。途中のフリープレイ（1 手以上進めたもの）があれば、消えることも示す。ホームの「読み込めない盤面です」は、ゲームを開くと消える。旧 URL では読まない（記録の無い端末は、クエリごと新しい URL へ移ってから読む）。
- 外から来る値なので、軽い検査から順に確かめる。どれかで断ったら、ホームに「読み込めない盤面です」と出す。
  - クエリが 2048 文字以内で、`p` が 1 つ、81 桁の数字だけ（値はデコードしない。`%` エンコードや全角数字は断る）。
  - ヒントが 17〜80 個（81 個だと解き終えられない）。同じ行・列・ブロックに同じ数字が無い。
  - 解が 1 つ（2 つ目で打ち切る）。数字を置く回数は 20 万回まで（よく知られた難問でも 12 万回ほど。解の無い・多い盤面には数百万回掛かるものがあり、打ち切って断る。手元の Mac で最悪 220ms ほど）。
- 難易度は手筋の判定で決める（レベル 1 かんたん、2 ふつう、3・4 むずかしい、5 エキスパート、6 鬼）。`d` はその範囲に入るときだけ使う（極は鬼と同じレベル 6 なので、`d=extreme` のときだけ極）。
- 始めた問題はふつうのフリープレイと同じで、始めた数・クリア・実績に数える（ランキングには関係しない）。シードは `shared:<81 桁>`。
- 「間違える前まで戻す」も、1 つの盤面で解けるかを確かめる置く回数を 20 万回までにする（作った問題なら数千回で終わる）。確かめ終わらない盤面まで戻したら、そこで止める（それより前の手は消さない）。

## 盤面の入力

紙やほかのアプリの問題を手で入れて、フリープレイとして遊ぶ（`src/components/Entry.tsx`、`src/lib/client/entry.ts`）。カメラや画像からの読み取りは無い。

- ホームのフリープレイの「盤面を入力」で開く。マスを選んで数字を入れる・消す（数字パッド・1〜9・矢印・Backspace・戻す・進む。Shift+1〜9 も数字として入れる）。メモ・色・複数選択・ヒント・一時停止は使わない（キーを押しても何もしない）。
- 盤面はゲームと同じ表（grid）で読み上げる（Tab で止まるのは 1 マス、矢印でフォーカスも動く）。入れた数字・消したことは盤面の外の欄（`role="status"`）で知らせる。
- 同じ行・列・ブロックに同じ数字があると、その場で両方のマスを間違いとして示す（赤と波線の下線。読み上げでは「間違い」）。
- 盤面の上に、ヒント（入れた数字）の数「n/81」と、始められない理由（始められるなら難易度）を出す。理由は読み上げの欄（`role="status"`）で知らせる。
- 「始める」は、共有された盤面と同じ検査（`src/lib/client/sharedPuzzle.ts` の `checkPuzzle`）を通ったときだけ押せる。理由は確かめる順に「ヒントが少なすぎます（17 個以上）」（16 個以下）・「空きマスがありません」（81 個）・「矛盾があります」（重複）・「解がありません」・「解が 1 つに決まりません」・「解が 1 つか確かめきれません」（置く回数が 20 万回を超える）。
- ヒントの数と重複は入れるたびに確かめる。解が 1 つかは、入力が 300ms 止まってから確かめる（確かめ終わるまで「始める」は押せない）。確かめる処理は画面と同じスレッドで動き、その間は入力を受け付けない（置く回数の上限で、手元の Mac で最悪 140ms ほど。ふつうの問題は数 ms）。
- 押すと「入力した問題を始めますか？」を出し、そこで「始める」を押したときだけフリープレイとして始める。途中のフリープレイ（1 手以上進めたもの）があれば、消えることも示す。「やめる」なら何も変えず、入れた盤面もそのまま。
- 難易度は手筋の判定で決める（共有された盤面と同じ。レベル 6 は鬼で、極にはならない）。シードは `shared:<81 桁>`。始めた問題は共有された盤面と同じく、始めた数・クリア・実績に数える（ランキングには関係しない）。クリアの結果の「結果を共有」で、その盤面を開く URL を送れる。
- 入れた盤面は保存しない（端末にもサーバーにも送らない。画面を離れると消える）。URL からは受け取らない（共有の URL は「盤面の共有」の確かめるシートを通る）。

### 表示の設定

- 保存先は設定（`sudoku:settings`）の `theme`（`auto`・`light`・`dark`）と `textSize`（`normal`・`large`・`xlarge`）。決まった値でなければ既定（自動・標準）にする。サーバーには送らない。
- `<html>` の `data-theme`・`data-text-size` で効かせる（既定では付けない）。開いたときは `<head>` のインラインのスクリプト（`src/lib/client/display.ts` の `DISPLAY_SCRIPT`）が最初の描画の前に付けるので、既定の見た目が一瞬出ることはない。設定を変えたときは `applyDisplay` で付け直す。localStorage が使えない・値が壊れているときは何も付けない（例外は出さない）。
- テーマ:
  - ダークの色は、`@media (prefers-color-scheme: dark)` の中の `:root:not([data-theme="light"])` と `:root[data-theme="dark"]` の 2 か所に同じ値を書く（`src/lib/client/display.test.ts` で同じか確かめる）。テーマを選んだときは `color-scheme` もそのテーマにする。
  - theme-color は、自動では端末の設定に合わせた 2 つ（`src/app/layout.tsx` の `viewport`）。テーマを選んだときは、その色の theme-color（`#theme-color-fixed`）を `<head>` の先頭に足す（先頭の当てはまるものが使われる）。その値は大文字で書く（React は hydration で `<meta>` を name と content で探すので、同じ文字列だと端末の設定に合わせたものと取り違える）。manifest の `theme_color` はライトの色のまま。
- 文字サイズ:
  - 文字の大きさは rem で書き、ルートの大きさを `--text-scale`（標準 1・大 1.15・特大 1.3）で変える。標準はブラウザの既定の大きさ（ふつう 16px）のまま。
  - 盤面の大きさは画面で決まるので変えない。盤面の数字には同じ倍率を、メモには 1.2 倍までを掛ける（3×3 の枠に収まるように）。
  - フリープレイと練習のツールの名前は、並びの幅に合わせた大きさを超えない。ロゴ・結果の見出しと点数・連続日数・引き継ぎコード・ツールのバッジは大きくしない。
- 拡大: viewport に `maximum-scale`・`user-scalable` を付けない。ゲームの画面（`.game`）とボタンは `touch-action: manipulation` でダブルタップの拡大を止める。盤面は `touch-action: none`（なぞって選ぶため。盤面の上ではピンチでも拡大しない）。
- 既知の限界: 実機の iOS Safari とホーム画面に追加したアプリで、ダブルタップで拡大しないこと・ピンチで拡大できること・ステータスバーなどの色が選んだテーマに合うことは確かめていない。

### スコア

- 正しい数字を置くたびに、難易度の基本点（かんたん 50 〜 極 300）× コンボで得点する
  - コンボ：続けて正解するたびに +5%（最大 +50%）
- 行・列・ブロックのすべてのマスで得点すると、ユニットごとに基本点 × 3 のボーナス
- 間違えると基本点ぶん減点してコンボが切れる。同じマスで得点するのは 1 回だけ
- 解き終えたら時間ボーナス：基本点 × 空きマス数 × 2 × (1 − 経過時間 ÷ 基準時間)。基準時間（かんたん 10 分 〜 極 120 分）を過ぎたら 0
- 速さは解き終えるまでの時間だけで測る。手と手の間隔で測ると、メモで解いておいて最後にまとめて置くだけで点が増えてしまう（鬼で 1.5 倍）
- 計算は `src/lib/game/score.ts`。ブラウザの表示とサーバーの記録で同じものを使う

### ランキングの公正さ

- 今日の一問は日付と難易度から決まり、最初に作った問題をサーバーに固定します。解答はブラウザに送りません。
- 順位は点数の高い順、同点ならタイムの速い順です。点数は、提出された手の記録（マス・数字・順番）とサーバーが測った経過時間から、サーバーが計算し直します。
- 時間はサーバーが計測します（開始を受け付けた時刻から、正しい解答を受け取った時刻まで）。一時停止はできません。
- 同じプレイヤーが開始し直しても最初の開始時刻が使われ、記録は最初のクリアの 1 回だけです。15 秒未満のクリアは記録しません。
- プレイヤーは端末ごとの匿名 ID とニックネームで識別します。ログインは任意なので、ID を作り直す不正までは防げません。

### ランキング API の回数制限と本文の上限

- 回数制限（固定窓。超えたら 429 `rate limited`。IP の扱い（IPv6 の /64 と /48）は通知の購読と同じ。`src/lib/server/ranking.ts` の `RANKING_RATE_LIMITS`）:
  - 今日の一問の開始（`POST /api/daily/start`）: IP ごとに 1 時間 240 回。開始し直しも数える。
  - 引き継ぎコードの発行（`POST /api/player/transfer`）: IP ごとに 1 時間 10 回、playerId ごとに 24 時間 100 回、全体で 1 時間 300 回。全体の上限を超えたら 503 `too many codes` と `Retry-After`（窓が変わるまでの秒数）（コードは 1 件 約 4KB で 24 時間残るので、保存先の容量を守る。超えると、その 1 時間が終わるまで誰も発行できない）。その 1 時間の全体の 211 回目（7 割の 210 回より後）からは、IP ごとに 2 回（それまでの回数を含む。IPv6 の /48 は 16 回）に下げる（混雑の段）。IP・playerId・全体の順に数え、先の制限で断った分は後の回数に数えない。混雑かどうかは全体を数えた戻り値（何回目か）で決める（読んでから数えると、同時に届いた要求がそろって混雑の前と読む）。全体を数えたあとで断った要求（混雑の段の 429・全体の上限の 503）は、IP の枠で断ったときと同じく、playerId と全体の回数から戻す（IP の回数にだけ残る）。全体に残るのは発行した分だけなので、実際に 300 件発行されるまで窓は閉じない（同時に多数届くと、戻す前の短い間は 503 になりうる）。playerId も戻すのは、混雑や満杯はその利用者のせいではなく、試し直すたびに 1 日の枠を減らさないため。全体を超えていても、混雑の段に当たる要求は 429。端末は全体の上限で「いまは発行できません。しばらくしてからもう一度試してください」と出す。
  - 引き継ぎコードの使用（`POST /api/player/claim`）: IP ごとに 1 時間 100 回。見つからないコード（404）も数える。断った要求ではコードを使わない。
  - 数えるのは形の検査（400）を通った要求だけ。今日の一問の送信・名前の変更・表と履歴の取得は数えない。
  - 端末は 429 で「しばらくしてからもう一度試してください」と出す。
- 本文の上限（UTF-8 のバイト数。超えたら 413）: 今日の一問の送信は 64KB（2,000 手の記録が収まる）、引き継ぎコードの発行は 8KB（保存する中身は 4096 バイトまで）、ほかは 1KB。
- `GET /api/leaderboard` は、`playerId` の無い要求の成功した応答だけ `Cache-Control: public, s-maxage=10, stale-while-revalidate=30`（CDN のキャッシュ）。`playerId` 付きとエラーは `no-store`。
- 想定外のエラーは、エラーの名前だけを記録する（`request failed (<名前>)`。Upstash のエラーには送ったコマンド＝playerId・引き継ぎコード・記録が含まれうる）。どの API かは Vercel のログの要求のパスで分かる。通知・アカウントの API も同じ。
- 既知の限界:
  - IP ごとの枠（ランキング・アカウント・通知の購読のすべて）は、IPv6 では /64 と、その 8 倍の上限の /48 で数える。/64 を 1 つしか使わない人では /48 の巻き込みは起きない（/64 の上限で止まり、/48 には数えない）が、/64 を 8 つ以上使えると、同じ /48 の他人もまとめて 429 にできる（世帯ごとに /56 を配る ISP・携帯のキャリアの共有プール・大学など。/56 の段は入れていない）。IPv4 の NAT の内側でも、同じ IP の利用者は枠を共有する。
  - 混雑の段では、/64 の 3〜10 回目（混雑の段で断られる要求）も /48 の回数に残る。そのため、/64 を 2 つ使って 10 回ずつ送るだけで /48 の回数が 16 を超え、同じ /48 の他人の発行も 429 になる（上の「/64 を 8 つ以上」は、ふだんの上限での話）。
  - IPv6 の要求は、IP の枠を数える保存先のコマンドが IPv4 より多い（IPv4 は INCR と EXPIRE の 2。IPv6 は /64 を通ると /48 の分を足して 4、/48 で断っても 4。/64 で断れば 2）。
  - 引き継ぎコードの全体の上限は、多数の IP から 1 時間埋められると、その間は誰も発行できない（旧 URL の「記録を移して開く」も含む）。IP の回数が 3 回目以降の要求は、それまでに発行された数が 210 件未満のときしか通らず、211 件目からは IP ごとに 2 回（/48 ごとに 16 回）までしか発行できない。断った要求は全体に残らないので、埋めるには 1 時間に IPv4 で 45 個以上、IPv6 で /64 を 8 つ以上ずつ持つ /48 が 6 つ以上要る（210 + 2 × 45 = 300、210 + 16 × 6 ≥ 300。一斉に送り、各 IP の 1・2 回目が 211 件目より後に通る最も悪い順のときの値で、順に送るなら IPv4 で 66 個、/48 で 9 つ）。
  - 混雑の段に入ると、共有の IP（携帯の CGNAT・学校や会社の NAT）で、その 1 時間にすでに 2 回以上発行されていた利用者は、その 1 時間の残りは発行できない（429）。
  - 名前の変更（`POST /api/player`）は回数を制限せず、どの playerId でも受け付けるので、名前の表（`sdk:names`。期限なし）を増やせる。遊んだことのある playerId だけに絞ると、遊ぶ前に設定で付けた名前（アカウントのパスキーの名前に使う）を保存できなくなる。
  - playerId ごとの制限は、playerId を作り直せば回避できる。主な歯止めは IP ごとの制限で、多数の IP を使われると防げない。429 で断った要求も、カウンタの分だけ保存先のコマンドを使う。Vercel の WAF・レート制限のルールの併用を勧める。
  - アプリの表の取得は必ず `playerId` を付けるので、CDN のキャッシュが効くのはアプリ以外からの要求だけ。

npm test             # 単体テスト（vitest）

アカウントの E2E は、パスキーの操作をデスクトップ（Chromium）の仮想の認証器（CDP）で動かす。テストのサーバーには `WEBAUTHN_ORIGIN=http://localhost:3100` と空の Redis の接続先（保存先はメモリ）を渡す（`playwright.config.ts`）。`E2E_BASE_URL` を付けたとき（本番やプレビューに向けたとき）は、アカウントの E2E を飛ばす。
`reuseExistingServer: true` なので、3100 番で既にサーバーが動いていると、そのサーバー（と、その環境変数の Redis の接続先）をそのまま使う。CI と、ふだんのローカルの実行（サーバーを起動していない）では起きない。起動済みのサーバーがあれば止めてから実行する。
E2E の要求は、アカウントと引き継ぎ（URL の移行を含む）の E2E（テストごとに `x-forwarded-for` を変える。`ipHeaders`）を除き、どれもループバックの IP（Next.js が `x-forwarded-for` に付ける）から届き、iPhone とデスクトップの分が回数制限の同じ枠に積み上がる。上限は、1 回の実行で 1 つの IP から届く回数の 3 倍以上にする。テストを足したら確かめる。

- ドメインは 2 つとも Production に付ける（新しい URL `nanpure-game.vercel.app` と旧 URL `sudoku-xi-five.vercel.app`）。旧 URL に Vercel の転送（Redirect）は設定しない（記録のある端末が旧 URL の記録に戻れなくなる。「URL の移行」を参照）。

### セキュリティヘッダー

- 全パス（ページ・API・静的ファイル・`/sw.js`）に付ける（`next.config.ts` の `headers()`。中身は `src/lib/security-headers.ts`）。
- CSP: スクリプト・画像・通信などの先は同じ origin だけ。nonce は使わず、インラインの `<script>` とスタイルは `'unsafe-inline'` で許す（nonce にするとページを毎回サーバーで描画することになり、関数の実行が増える）。表示の設定を最初の描画の前に付ける `<head>` のスクリプトも、これで動く。属性のハンドラ（`onclick` など）は使っていないので `script-src-attr 'none'` で止める。`'unsafe-eval'` は `next dev` のときだけ足す（`next.config.ts` の phase で見る）。外部のスクリプト・画像・通信先を使うときは CSP にも足す（足さないと読み込めない）。
- iframe への埋め込みは `frame-ancestors 'none'` と `X-Frame-Options: DENY` で止める。
- `Referrer-Policy: strict-origin-when-cross-origin`。`no-referrer` などにしない（新しい URL は旧 URL から開かれたかを `document.referrer` で見る。「URL の移行」を参照）。
- ほか: `X-Content-Type-Options: nosniff`、`Cross-Origin-Opener-Policy: same-origin`（ポップアップと `window.opener` は使っていない）、`Permissions-Policy` でカメラ・マイク・位置情報だけを止める（触覚・通知・パスキー・共有は止めない）。
- `Strict-Transport-Security` は Vercel が付けるので、ここでは付けない。
- Service Worker は保存した応答をヘッダーごと返すので、ヘッダーを変えたら `public/sw.js` の `CACHE` の版を上げる（入れ替わって取り直す）。
- 既知の限界: `'unsafe-inline'` を許すので、HTML に入り込んだインラインの `<script>` は止められない（外部のスクリプトの読み込みと、fetch・画像などでほかの origin へ送るのは止める。ページの移動・WebRTC（`RTCPeerConnection` の STUN/TURN）・DNS のプリフェッチで送るのは止められない）。プレビューで Vercel のツールバー（`vercel.live`）は読み込めない。

### アカウント（パスキー）

- 任意のログイン。パスキー（WebAuthn）だけを使い、メールアドレス・パスワード・外部サービスのログインは使わない。ログインしなくても今までどおり遊べる。端末側は `src/lib/client/account.ts` と、設定の「アカウント」（`src/components/Sheets.tsx` の `AccountSheet`）。
- 環境変数: `WEBAUTHN_ORIGIN`（秘密の値ではない）。本番は `https://nanpure-game.vercel.app`（末尾の `/` なし）。受け付けるのは https（ホストが IP アドレスでないもの）と http の `localhost` だけ。Vercel 上で未設定（プレビューを含む）か受け付けない形なら、`/api/auth/*` は 503。Vercel 以外で未設定なら `http://localhost:3000`。
- RP ID は `WEBAUTHN_ORIGIN` のホスト名。変えると登録済みのパスキーが使えなくなる（回復の手段は無い）。origin と RP ID は環境変数だけで決め、リクエストの Host からは決めない。`GET /api/auth/me` は、Host が `WEBAUTHN_ORIGIN` のホストと違えば（旧 URL など）503 を返す。
- API（本文はすべて JSON。GET 以外は、`Origin` が `WEBAUTHN_ORIGIN` と一致しなければ 403、`Content-Type` が `application/json` でなければ 415）:
  - `GET /api/auth/me`: `{ account }`（`playerId`・`name`・`passkeys`（件数）・`stats`（同期した記録）。ログインしていなければ `null`）。
  - `POST /api/auth/signup/options`（`{ playerId }`）・`/signup/verify`（`{ response }`）: アカウントを作ってログインする。
  - `POST /api/auth/login/options`（`{}`）・`/login/verify`（`{ response }`）: ログインする。
  - ログインが必要なもの（Cookie が無い・無効なら 401 で、Cookie を消す）:
    - `POST /api/auth/logout`（`{ scope: "this" | "others" }`）: `others` はこの端末以外のセッションを消す。
    - `POST /api/auth/passkeys/options`（`{}`）・`/passkeys/verify`（`{ response }`）: ログイン中のアカウントにパスキーを足す。`{ account }` を返す。
    - `PUT /api/auth/stats`（`{ stats }`）: 記録を同期する。合わせた記録 `{ stats }` を返す。
    - `POST /api/auth/merge`（`{ fromPlayerId }`）: 今日の一問の履歴を取り込む。写した件数 `{ merged }` を返す。
    - `DELETE /api/auth/account`（本文は `{}`。本文が無いと 400）: アカウントを消し、この端末の Cookie も消す。
- アカウントを作ると、端末のプレイヤー ID をアカウントに紐づける。1 つのプレイヤー ID は 1 つのアカウントだけ（紐づけ済みなら 409）で、紐づけは後から変えない。パスキーの user.id はアカウント ID（ランダムな UUID）で、プレイヤー ID は入れない。パスキーに付く名前はランキングの名前（無ければ「プレイヤー」）。
- ログインの状態は Cookie（`__Secure-sdk_auth`。http の localhost では `sdk_auth`）で持つ: `Path=/api/auth; HttpOnly; Secure; SameSite=Strict`、90 日。トークンは応答の本文に出さない。`GET /api/auth/me` で有効だと確かめるたびに、セッションと Cookie の期限を 90 日に延ばす。
- ログインの失敗（知らないパスキー・別のアカウントのパスキー・検証の失敗）は、どれも同じ 401 `login failed`。
- パスキーの追加: 登録済みのパスキーは options の `excludeCredentials` に入れる。登録済みのパスキーは 409。
- 記録の同期: 端末のフリープレイの記録を送ると、保存済みの記録と難易度ごとに良い方・多い方で合わせて保存し、合わせた記録を返す（何度送っても同じ結果になる）。
- 履歴の取り込み: `fromPlayerId`（ログイン前に端末で使っていたプレイヤー ID など）の今日の一問の履歴を、アカウントのプレイヤー ID に写す。同じ日・難易度はアカウント側を残す。ランキングの行と名前は移さない。紐づき済みのプレイヤー ID からは写さない（0）。
- アカウントの削除: 消すのはアカウント・パスキー・セッション・同期した記録・プレイヤー ID の紐づけ。ランキング・今日の一問の履歴・名前・通知の購読（プレイヤー ID のもの）は残す。消したパスキーではログインできない（401）。プレイヤー ID を持つ端末はそのまま遊べ、同じプレイヤー ID でアカウントを作り直せる。紐づけは最初に消すので、途中で失敗しても作り直せる（残りはもう一度消せば消える）。
- 登録で受け付ける attestation は none だけ（ほかの形式は検証せずに 400）。ほかの形式ではライブラリが証明書を検証し、証明書に書かれた CRL の URL へサーバーから通信しうるため。
- 端末の動き:
  - 開いたときに `GET /api/auth/me` でログインの状態を確かめる。旧 URL では確かめず、アカウントの項目を出さない（パスキーは新しい URL に結びつく）。ログイン中なら、端末のプレイヤーがアカウントのプレイヤーと違うときだけ履歴を取り込み（`merge`）、アカウントのプレイヤーに切り替え、記録を合わせて同期する。503 と形の違う応答ではアカウントの項目を出さない。通信の失敗などでは項目を出さず、ホームに戻ったときに確かめ直す。確かめている間とログイン中は、引き継ぎのコードを入れさせない。旧 URL から開いた `#code=` のシートは、確かめ終わるまで待ち、ホームでほかのシートが無くなってから開く（ログイン中なら開かない。コードでアカウントのプレイヤーを置き換えない）。
  - アカウントの項目はホームの設定にだけ出す（ゲームや練習の途中にプレイヤーが替わると、今日の一問の送信が通らず、ログアウトの後に途中の盤面が書き戻される）。
  - 記録の同期は、ログイン・作成の直後、ログイン中にホームに戻ったとき、ログアウトの前。送ってもアカウントの記録が変わらないときと、送っている途中は送らない（端末には何も保存しない）。
  - パスキーの操作（作成・ログイン・追加）の options は、アカウントのシートを開いたときと操作の後に先取りし、ボタンを押したら待たずに WebAuthn を呼ぶ（Safari はユーザーの操作の中でないとパスキーの画面を出さない）。取得から 4 分を過ぎた options は使わない。まだ取れていない・期限切れなら始めずに取り直し、「もう一度試してください」と示す（もう一度押せば始まる）。取れなかったらその理由を示す。取り直すのは、シートを開いたとき・操作の後・押して始められなかったときだけ（challenge の発行の回数制限に数えるので、定期的には取り直さない）。紐づき済み・パスキーが上限の 409 は、プレイヤー（追加はログイン中のアカウント）が変わるまで取り直さない。パスキーの画面を閉じた（`NotAllowedError`・`AbortError`）ときは何も示さない。
  - ログアウトは、まだ送っていない記録をアカウントに送り、サーバーでセッションを消せたときだけ端末の記録を消す。送れない（通信の失敗・429 など）ときはログアウトせず、何も消さない。もうログインしていない（401）ときは、送れなくても消す。消すのは `sudoku:player`・`sudoku:stats`・`sudoku:history`・`sudoku:achievements`・`sudoku:result:*`・`sudoku:daily:*`（プレイヤー・フリープレイの記録・履歴・実績・今日の一問の結果と途中の盤面）。通知の印（`sudoku:reminder`）・設定・途中のフリープレイ・練習の進み具合などは残し、通知の購読は新しいプレイヤーに移す。
- サーバーに保存するもの: アカウント（ID・プレイヤー ID・作成日時）、パスキー（credential ID・公開鍵・counter・transports・バックアップの状態・作成日時・最後に使った日時）、セッション（トークンの SHA-256・アカウント ID・期限。最後の確認から 90 日で消える）、同期した記録（難易度ごとの記録。4096 バイトまで）、challenge（300 秒で消える）。メールアドレスなどの個人情報は保存しない。
- 回数制限（超えたら 429。IP の扱いは通知の購読と同じ）: challenge の発行（options の API。紐づき済みの playerId への 409 も数える）は IP ごとに 1 時間 60 回、アカウントの作成は IP ごとに 1 時間 5 件（検証を通ったものだけ数える）、記録の同期はアカウントごとに 1 時間 120 回、履歴の取り込みはアカウントごとに 1 日 20 回。
- 件数の上限: アカウントは全体で 20,000 件（超えたら作成は 503）。パスキーは 1 アカウント 10 件（達していたら 409。同時に足しても超えない）。セッションは 1 アカウント 20 件（超えたら最後に使ったのが古いものから消す）。
- サイズの上限: 本文は検証 API が 16KB、記録の同期が 8KB、ほかは 1KB。登録の attestationObject は base64url で 4096 文字、保存する公開鍵は 1KB、同期した記録は 4096 バイト。
- 既知の限界:
  - プレイヤー ID は、既存の API ではそれを知っていれば使える秘密のまま。他人のプレイヤー ID を知っていれば、まだ紐づいていなければ自分のアカウントに紐づけられ（先着 1 つ）、履歴の取り込みで、そのプレイヤーの履歴の空いている日に別のプレイヤー ID の行を書き込める（履歴の読み取りは既存の `GET /api/player/history` でできる）。
  - プレイヤー ID は GET のクエリ（`/api/leaderboard`・`/api/player/history`）に入り、Vercel のログに残る。
  - RP ID は変えられない（ドメインを変えると、登録済みのパスキーではログインできない）。
  - 2 台で同時に遊ぶと、記録は良い方・多い方で合わせるので、回数（始めた数・クリア数など）は足されず、少なく数えられる。
  - 記録の同期は読んでから書くので、2 台が同時に同期すると片方の分が保存されないことがある（その端末が次に同期したときに戻る）。
  - ログインなどで端末のプレイヤー ID が変わると、変わる前に始めた今日の一問の送信は 404 になる（アカウントの操作はホームからだけだが、途中でやめた今日の一問をログインの後に続けると起こる）。
  - パスキーの追加に再認証は無く、登録済みのパスキーの一覧・個別の削除も無い。同じ origin に XSS があれば、セッションの Cookie で攻撃者のパスキーを足せる（外す手段はアカウントの削除だけ）。
  - アカウントの削除と同時に書き込み（パスキーの追加・記録の同期・ログイン）があると、持ち主のいないパスキー・記録・セッションが残りうる（ログインや閲覧には使えず、容量を使うだけ）。
  - Redis や通信が途中で失敗すると、パスキーの追加で一覧に入らない（件数にも削除にも数えられない）パスキーが残ったり、上限を 1 件超えたりしうる。同じアカウントの削除が同時に 2 本走ると、その間に紐づけ直された別のアカウントの紐づけを消しうる。どちらも攻撃では起こせず、プレイヤー ID を知る者の権限は増えない。
  - ソフトウェアで作った偽の認証器でもアカウントは作れる。IP ごとの回数制限と全体の上限でしか抑えられないので、多数の IP を使われると全体の上限（20,000 件）を埋められうる。Vercel の WAF・レート制限のルールの併用を勧める。
  - iOS のホーム画面に追加したアプリでのパスキーの動作は、実機で確かめていない。
  - 登録で attestation に none を返さないクライアント（一部のパスワード管理アプリなど）では、作成・追加が 400 になり「作成できませんでした」「追加できませんでした」と出る。認証器にはサーバーの知らないパスキーが残る（ログインには使えない）。
  - 履歴の取り込みや記録の同期に失敗しても、ログインはそのまま続ける（取り込めなかった履歴は前のプレイヤーに残る。記録は次の同期で送る）。
  - ログアウトのときにセッションがもう無い（401。ほかの端末からのログアウトや期限切れ）と、まだ送っていない記録を送れないまま端末の記録を消すので、その分は失われる。
  - 「ほかの端末をログアウト」やセッションの期限切れの後も、その端末にはプレイヤー ID と記録が残り、ログインしていないプレイヤーとして遊び続けられる。プレイヤー ID は既存の API の秘密のままで、端末の外からは無効にできない。共有の端末では、ログアウトして端末の記録を消す。
  - ほかのタブは、ログアウトしても再読み込みするまで前のプレイヤーのままで、そのタブから今日の一問の送信などができる（タブの間の保存データの変化は見ていない）。
  - ログアウトには通信が要る。まだ送っていない記録の送信か、セッションを消す要求（`POST /api/auth/logout`）が、通信の失敗・429・5xx など 401 以外で失敗すると、ログアウトできない。
  - セッションの切れた端末で別の人がログインすると、その端末に残っていた前の人のフリープレイの記録が、ログインした人のアカウントに合わさる。

### リマインド通知（Web Push）

- 環境変数: `NEXT_PUBLIC_VAPID_PUBLIC_KEY`（公開鍵）、`VAPID_PRIVATE_KEY`（秘密鍵）、`VAPID_SUBJECT`（`mailto:` か `https://` で始まる連絡先）、`CRON_SECRET`（cron の認証）。1 つでも無いと、購読 API（`/api/push`）と cron は 503 を返す。
- 端末は公開鍵をビルドに埋め込まず、`GET /api/push`（`{ publicKey }`）で取る。503 や通信の失敗のときは、設定に「毎日の通知」を出さない。
- 端末は、通知をオンにしているとアプリを開くたびに購読を登録し直す（最後の登録から 400 日の期限を延ばす）。引き継ぎでプレイヤーが変わったときも、購読を新しいプレイヤーに移す。
- VAPID の鍵は `npx web-push generate-vapid-keys` で作る。鍵を変えると既存の購読は無効になる（端末が購読し直すまで届かない）。
- 通知の文言は端末側（`public/sw.js`）で固定し、届いた中身は読まない（VAPID の秘密鍵と購読の鍵が漏れても、任意の文言を出させない）。
- cron は毎日 UTC 11:00（日本時間 20:00）に `/api/cron/remind` を呼ぶ（`vercel.json`）。Vercel が `Authorization: Bearer ${CRON_SECRET}` を付ける。今日の一問を 1 問もクリアしていないプレイヤーの購読に、1 日 1 回送る。
- 受け付ける購読の送信先は、Apple（`push.apple.com` とそのサブドメイン）・FCM（`fcm.googleapis.com`）・Mozilla（`updates.push.services.mozilla.com`）・Windows（`notify.windows.com` とそのサブドメイン）の https だけ。
- 購読の登録は playerId ごと。同じ endpoint を別の playerId に移すには auth の一致が必要。
- 新規の登録（保存済みでない endpoint）は回数を制限する: 登録元の IP ごとに 1 時間 20 件、playerId ごとに 24 時間 10 件（超えたら 429）。既存の購読の更新・移動と解除は制限しない。IP は `x-forwarded-for` の最初の要素（無ければ `x-real-ip`、どちらも無ければ 1 つにまとめる）で、IPv6 は /64 ごとに数え、同じ /48 はその 8 倍の上限でまとめても数える（/64 で断った分は /48 に数えない。IPv4 射影は IPv4 として数え、ゾーン ID は落とす）。カウンタの名前は SHA-256 にして保存する。Vercel 以外で動かすときは、これらのヘッダーを付け直すプロキシの後ろに置く（クライアントが `x-forwarded-for` を指定できるので、偽装で回避されるうえ、他人の IP を指定してその IP の枠を使い切ることもできる）。
- サーバーに保存するもの: 購読の endpoint・鍵（p256dh, auth）・プレイヤー ID・登録日時。最後の登録から 400 日で消える。1 人 5 件まで（超えたら古いものから消す）、全体で 20,000 件まで。
- 送れない購読は消す: 404・410 と鍵の誤りはすぐ。ほかの失敗（名前解決・接続・状態コードなど）は 5 日続いたら消す（送れた日に数え直す。送信の期限切れと時間の上限で送らなかったものは数えない。429 と 503 は購読の故障とみなさず数えない）。失敗した日は購読ごとに保存し、最後の失敗から 3.5 日で消える。
  - 失敗の日は、その日に同じプッシュサービス（Apple・Windows・Mozilla・FCM）へ 1 件以上送れたときだけ数える（設定の誤りや、そのサービスだけの障害・拒否で購読を失わないため）。名前解決の失敗（存在しないサブドメインなど）と、保存済みの endpoint が今の検査を通らないものは、どのサービスでも 1 件送れていれば数える。
- 既知の限界: 購読 API には認証が無いので、多数の IP を使われると全体の上限（20,000 件）を埋められうる。利用者のいないサービス（例 `*.notify.windows.com`）の配下に作られた購読が 403 などを返し続けると、消えずに残る。完全に防ぐには Vercel の WAF・レート制限のルールなどを併用する。
- cron の応答は件数と、失敗の種類別の件数（`failures`: `blocked`・`dns`・`timeout`・`deadline`・`http4xx`・`http5xx`・`invalid`・`other`）だけ。
