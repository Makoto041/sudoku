# ナンプレ

置くたびに気持ちいい音が鳴る、シンプルなナンプレ（数字を埋めるパズル）。毎日の「今日の一問」で、全員が同じ問題を解いて点数を競えます。

「数独」はニコリの登録商標なので、アプリ名には使わない。
iPhone では Safari の共有メニューから「ホーム画面に追加」すると、アプリとして遊べます（PWA）。

**プレイ: https://nanpure-game.vercel.app**

## 遊び方

- **アプリ内の遊び方**: ホーム右上の「?」か設定から開く。ルール・操作・点数・今日の一問の決まり・難易度と手筋・キー操作がある。
  - ホームから開いたときは、ネイキッドシングルの練習への入口もある。
  - 初めて開いたときは、ホームに案内を 1 行出す。閉じるか遊び方を開くと、それ以降は出さない。
- **難易度**: かんたん・ふつう・むずかしい・エキスパート・鬼・極。鬼は人の手筋では解けない水準、極は鬼の候補をたくさん作って、仮定を何段も重ねないと解けないものを選んだ問題。
- **今日の一問**: 難易度ごとに 1 日 1 問。全員が同じ問題で、最初のクリアタイムがランキングに載ります。日付は日本時間 0 時に切り替わります。
- **フリープレイ**: 好きな難易度で何問でも。ヒントと一時停止が使えます。オフラインでも遊べます。
- **手筋の練習**: 手筋ごとに用意した局面で、置けるマスに数字を置くか、消せる候補をメモから消す。ヒントで答えを見られる。解いた局面の数は端末にだけ残る（引き継ぎの対象外）。
- 操作: マスをタップ → 数字。メモはメモを ON にしてから数字。盤面をなぞるか Shift / Ctrl / Cmd+クリックで複数のマスを選ぶと、数字は選んだ空きマスのメモにまとめて付け外しし、消すはメモだけを消す。色を ON にすると、数字パッドが 9 色に変わり、選んだマスに色を付け外しする（消すは色だけを外す）。キーボードでは 1〜9、Shift+数字でメモ、矢印で移動、N でメモ切替、C で色切替、Backspace で消す、Z で戻す、Shift+Z で進む、H でヒント（今日の一問を除く）。
- **記録**: 今日の一問の連続日数とカレンダー、合計プレイ時間（フリープレイのクリアと途中でやめた分、今日の一問のクリア）、難易度ごとの記録。難易度ごとの記録は、今日の一問がクリア数・平均時間・最速・最高点・平均点、フリープレイが始めた数・クリア数・クリア率・平均時間・最速（ヒントなし）・ノーミス最速（ヒント・ミスなし）・最高点。フリープレイの始めた数は記録を取り始めた版から数え、クリア率と平均時間はそれ以降に始めた・クリアした分で出す（平均時間はヒントを使ったクリアも含む）。
- **実績**: 記録画面に一覧がある。今日の一問・フリープレイ・手筋の練習の記録から判定し、新しく解除したらクリアの結果か練習の正解に 1 行出す。解除した日は端末にだけ残る（引き継いだ先では、移した記録から判定し直す）。
- **引き継ぎ**: 設定でコードを発行し、別の端末で入力すると、プレイヤー（ID と名前）とフリープレイの記録を移せる。コードは 24 時間有効で 1 回だけ使える。今日の一問の記録はサーバーにあるので、そのまま見られる。
- 設定: 効果音・振動、間違いの表示、同じ数字や行・列・ブロックの強調、残りの数の表示、揃ったときの光、周りのメモの自動消去、ヒントの前の確認を、それぞれオン／オフできます。点数には影響しません。
- **毎日の通知**: 設定の「毎日の通知」でオンにすると、今日の一問を 1 問もクリアしていない日の 20 時（日本時間）に通知が届く。iPhone・iPad では、ホーム画面に追加したアプリ（iOS 16.4 以降）でだけ設定できる。端末にはオンにしたことだけを保存する（引き継ぎの対象外）。サーバーに保存するものは「リマインド通知（Web Push）」を参照。

## URL の移行

本番の URL を https://sudoku-xi-five.vercel.app から https://nanpure-game.vercel.app に移した。端末の記録は URL（origin）ごとに別なので、旧 URL の記録は新しい URL からは見えない。旧 URL も同じデプロイが配り、開いた端末側で見分けて案内する（`src/lib/client/move.ts`、`src/components/App.tsx` の起動処理）。

- 旧 URL で記録の無い端末は、同じパスとクエリで新しい URL へそのまま移る（旧 URL には何も保存しない）。
  - 記録は中身で判定する（`hasLocalData`）: 名前のあるプレイヤー、フリープレイの記録、途中の盤面、練習の進み具合、今日の一問の結果・途中の盤面、履歴、通知の印、通知をオンにしたまま移った印のどれか。開いただけで保存するもの（名前の無いプレイヤー・実績・空の履歴）と設定は記録とみなさない。見落とすと旧 URL の記録に戻れなくなるので、保存データの種類を増やしたらここに足す。
- 旧 URL で記録のある端末は、ふだんどおり遊べる。開くたびに「新しい URL へ移る」シートを出し（閉じられる）、ホームに閉じられない案内を出す。ホーム画面への追加は案内しない。
  - 「記録を移して開く」で引き継ぎコードを発行し、新しい URL を `/#code=XXXXXXXX` で開く。新しい URL では「引き継ぐ」を押したときだけコードを使う（開いただけでコードを使い切らないように）。新しい URL に記録があれば、置き換わることを示す。
  - 新しい URL が受け取るシートを自動で開くのは、旧 URL のページから新しく開かれたとき（`document.referrer` の origin が旧 URL で、読み込みの種類が `navigate`）だけ。ほかのページから `#code=` のリンクを開いたときと、再読み込み・戻る/進むで開き直したときは、URL から消すだけでシートを出さない（他人が自分のコードを入れたリンクを送ったり、移った後のページの fragment を差し替えて読み込み直させたりして、1 回のタップでプレイヤーを差し替えるのを防ぐ）。
  - referrer を送らないブラウザや設定では、「記録を移して開く」を押しても新しい URL でシートが出ず、そのコードは使われないまま 24 時間で失効する。この場合は旧 URL の設定の「コードを発行」で出したコードを、新しい URL の設定の「コードを入力」で入れる（通知については既知の限界を参照）。
  - iOS のホーム画面に追加したアプリは Safari と保存先が別なので、新しい URL を開かずにコードと手順を出す。新しい URL をホーム画面に追加し、その設定で「コードを入力」する。
  - 旧 URL の記録は消さない（いつでも旧 URL に戻れる）。旧 URL への転送（307/308）は入れていない。期限を決めて旧 URL を転送に切り替える段階（フェーズ 2）も入れていない。
- 移るのは引き継ぎと同じもの（プレイヤー ID・名前・フリープレイの記録）。設定・練習の進み具合・途中の盤面・実績の日付・通知の印は移らない。今日の一問の記録はサーバーにあるので、そのまま見られる。
- コードはクエリでなく fragment で渡す（サーバーのログや Referer に残さない）。新しい URL は開いてすぐ、通信の前に fragment を読んで URL から消す。旧 URL で受けたコードは使わずに消す。旧 URL のページの referrer の扱いを変える（`Referrer-Policy: no-referrer` など）と、受け取るシートが自動で開かなくなる。
- 通知: 移るときに旧 URL で通知をオンにしていたら、コードを発行した時点で旧 URL の購読を外し、旧 URL の端末に「通知をオンにしたまま移った」印（`sudoku:moved-with-reminder`）を残す。新しい URL で受け取るシートが開いて引き継いだときは、その後に「毎日の通知」の項目を出す（オンにし直す）。新しい URL から旧 URL に戻ってコードを発行し直したときも、この印で項目を出す。旧 URL で通知をオンにし直すと印は消える。印は旧 URL の端末内だけで、引き継ぎには含めない。シートが開かなかったときは項目を出さない（既知の限界を参照）。移っていない端末の旧 URL の購読はそのまま届き、通知を開くと旧 URL で案内が出る（購読は最後の登録から 400 日で消える）。
- URL を変えるときは `src/lib/site.ts` の `SITE_ORIGIN`・`LEGACY_HOST` を変える（`<link rel="canonical">` もここから作る）。
- 既知の限界:
  - referrer が届かないなどで新しい URL のシートが開かなかったとき、旧 URL で通知をオンにしていた端末では、旧 URL の購読は外れたまま、新しい URL でも通知はオフのままになり、通知が止まる（画面には何も出ない）。「記録を移して開く」で出したコードは使われないまま 24 時間で失効する。戻すには、旧 URL の設定で「毎日の通知」をオンにし直すか、旧 URL の設定の「コードを発行」で出したコードを新しい URL の設定の「コードを入力」で入れてから、新しい URL の設定で「毎日の通知」をオンにする。
  - 設定の「引き継ぎ」で旧 URL から新しい URL へ移ると、旧 URL の購読が残り、両方でオンにすると通知が 2 通届きうる（旧 URL の設定でオフにすれば止まる）。
  - `#code=` の URL は、消す前にブラウザの履歴に残りうる（コードは 24 時間有効で 1 回だけ使える）。
  - iOS のホーム画面に追加したアプリの保存先が Safari と別だという前提は、実機で確かめていない。

### スコア

- 正しい数字を置くたびに、難易度の基本点（かんたん 50 〜 極 300）× コンボで得点する
  - コンボ：続けて正解するたびに +5%（最大 +50%）
- 行・列・ブロックのすべてのマスで得点すると、ユニットごとに基本点 × 3 のボーナス
- 間違えると基本点ぶん減点してコンボが切れる。同じマスで得点するのは 1 回だけ
- 解き終えたら時間ボーナス：基本点 × 空きマス数 × 2 × (1 − 経過時間 ÷ 基準時間)。基準時間（かんたん 10 分 〜 極 120 分）を過ぎたら 0
- 速さは解き終えるまでの時間だけで測る。手と手の間隔で測ると、メモで解いておいて最後にまとめて置くだけで点が増えてしまう（鬼で 1.5 倍）
- 計算は `src/lib/game/score.ts`。ブラウザの表示とサーバーの記録で同じものを使う

### ランキングの公正さ

- 今日の一問は日付と難易度から決まり、最初に作った問題をサーバーに固定します。解答はブラウザに送りません。
- 順位は点数の高い順、同点ならタイムの速い順です。点数は、提出された手の記録（マス・数字・順番）とサーバーが測った経過時間から、サーバーが計算し直します。
- 時間はサーバーが計測します（開始を受け付けた時刻から、正しい解答を受け取った時刻まで）。一時停止はできません。
- 同じプレイヤーが開始し直しても最初の開始時刻が使われ、記録は最初のクリアの 1 回だけです。15 秒未満のクリアは記録しません。
- プレイヤーは端末ごとの匿名 ID とニックネームで識別します。ログインが無いので、ID を作り直す不正までは防げません。

## デプロイ

Vercel（Next.js）にデプロイし、Vercel Marketplace の **Upstash for Redis** をプロジェクトに接続します。
接続すると `KV_REST_API_URL` / `KV_REST_API_TOKEN` が自動で設定されます（`UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` でも可）。
環境変数を追加・変更したあとは再デプロイが必要です。

- ドメインは 2 つとも Production に付ける（新しい URL `nanpure-game.vercel.app` と旧 URL `sudoku-xi-five.vercel.app`）。旧 URL に Vercel の転送（Redirect）は設定しない（記録のある端末が旧 URL の記録に戻れなくなる。「URL の移行」を参照）。
- `VAPID_SUBJECT` は新しい URL（`https://nanpure-game.vercel.app`）にする。
- パスキーを入れるときは、`WEBAUTHN_ORIGIN` と RP ID を `src/lib/site.ts` の `SITE_ORIGIN` に合わせる。

### リマインド通知（Web Push）

- 環境変数: `NEXT_PUBLIC_VAPID_PUBLIC_KEY`（公開鍵）、`VAPID_PRIVATE_KEY`（秘密鍵）、`VAPID_SUBJECT`（`mailto:` か `https://` で始まる連絡先）、`CRON_SECRET`（cron の認証）。1 つでも無いと、購読 API（`/api/push`）と cron は 503 を返す。
- 端末は公開鍵をビルドに埋め込まず、`GET /api/push`（`{ publicKey }`）で取る。503 や通信の失敗のときは、設定に「毎日の通知」を出さない。
- 端末は、通知をオンにしているとアプリを開くたびに購読を登録し直す（最後の登録から 400 日の期限を延ばす）。引き継ぎでプレイヤーが変わったときも、購読を新しいプレイヤーに移す。
- VAPID の鍵は `npx web-push generate-vapid-keys` で作る。鍵を変えると既存の購読は無効になる（端末が購読し直すまで届かない）。
- 通知の文言は端末側（`public/sw.js`）で固定し、届いた中身は読まない（VAPID の秘密鍵と購読の鍵が漏れても、任意の文言を出させない）。
- cron は毎日 UTC 11:00（日本時間 20:00）に `/api/cron/remind` を呼ぶ（`vercel.json`）。Vercel が `Authorization: Bearer ${CRON_SECRET}` を付ける。今日の一問を 1 問もクリアしていないプレイヤーの購読に、1 日 1 回送る。
- 受け付ける購読の送信先は、Apple（`push.apple.com` とそのサブドメイン）・FCM（`fcm.googleapis.com`）・Mozilla（`updates.push.services.mozilla.com`）・Windows（`notify.windows.com` とそのサブドメイン）の https だけ。
- 購読の登録は playerId ごと。同じ endpoint を別の playerId に移すには auth の一致が必要。
- 新規の登録（保存済みでない endpoint）は回数を制限する: 登録元の IP ごとに 1 時間 20 件、playerId ごとに 24 時間 10 件（超えたら 429）。既存の購読の更新・移動と解除は制限しない。IP は `x-forwarded-for` の最初の要素（無ければ `x-real-ip`、どちらも無ければ 1 つにまとめる）で、IPv6 は /64 ごとに数え、SHA-256 にして保存する。Vercel 以外で動かすときは、これらのヘッダーを付け直すプロキシの後ろに置く（クライアントが `x-forwarded-for` を指定できるので、偽装で回避されるうえ、他人の IP を指定してその IP の枠を使い切ることもできる）。
- サーバーに保存するもの: 購読の endpoint・鍵（p256dh, auth）・プレイヤー ID・登録日時。最後の登録から 400 日で消える。1 人 5 件まで（超えたら古いものから消す）、全体で 20,000 件まで。
- 送れない購読は消す: 404・410 と鍵の誤りはすぐ。ほかの失敗（名前解決・接続・状態コードなど）は 5 日続いたら消す（送れた日に数え直す。送信の期限切れと時間の上限で送らなかったものは数えない。429 と 503 は購読の故障とみなさず数えない）。失敗した日は購読ごとに保存し、最後の失敗から 3.5 日で消える。
  - 失敗の日は、その日に同じプッシュサービス（Apple・Windows・Mozilla・FCM）へ 1 件以上送れたときだけ数える（設定の誤りや、そのサービスだけの障害・拒否で購読を失わないため）。名前解決の失敗（存在しないサブドメインなど）と、保存済みの endpoint が今の検査を通らないものは、どのサービスでも 1 件送れていれば数える。
- 既知の限界: 購読 API には認証が無いので、多数の IP を使われると全体の上限（20,000 件）を埋められうる。利用者のいないサービス（例 `*.notify.windows.com`）の配下に作られた購読が 403 などを返し続けると、消えずに残る。完全に防ぐには Vercel の WAF・レート制限のルールなどを併用する。
- cron の応答は件数と、失敗の種類別の件数（`failures`: `blocked`・`dns`・`timeout`・`deadline`・`http4xx`・`http5xx`・`invalid`・`other`）だけ。
